# Laptop hosting

This runs the official prebuilt LiteLLM 1.104.0 Windows package with the fork's pricing catalogue. The native Admin UI, database, virtual keys and reservations are used. The local service binds only to `127.0.0.1:4000`. A named Cloudflare Tunnel provides HTTPS and streaming through a hostname on your Cloudflare domain. Keep the laptop powered, online and awake

Install Python 3.12 or newer and run `Setup.ps1`. It creates an isolated Python environment and a private `.runtime/.env` file from `.env.example`. Fill in your own settings there. An existing deployment can import its saved settings with `Setup.ps1 -SecretsFile C:\private\settings.json -Hostname api.example.com`. `-UseExistingPython -PythonExe C:\venv\Scripts\python.exe` reuses an already prepared environment

Use a dedicated LiteLLM PostgreSQL database and a Redis TCP connection, including `rediss://` for TLS. Preserve the existing encryption salt when connecting to an existing database. Setup generates the matching Windows Prisma database client. Client generation does not change tables. An existing matching database needs no schema push. For a new database, follow the release's native migration process before starting; never schema-push a populated database

Run `Start.ps1`, then `Status.ps1`. The Admin UI is `http://127.0.0.1:4000/ui/`. Start registers a Windows task that survives closing the chat or terminal, starts again at Windows sign-in and retries failures up to five times. The task prevents duplicate starts of the same service. The project contains no Codex session ownership or session locks. The server requests Windows sleep prevention while running. This does not override lid closure, shutdown, loss of power or network changes. Use `Stop.ps1` for graceful shutdown and spend flushing; active requests may need several minutes to drain before the public tunnel disconnects

Connect the public address with `Connect-Cloudflare.ps1 -Hostname api.example.com`. Cloudflare opens its authorization page; select the domain you own. The script creates a named tunnel and a DNS route. It refuses to overwrite a conflicting DNS record. Run `Start-Tunnel.ps1` once the gateway is ready. Cloudflare reconnects the tunnel when connectivity returns. Its background task also starts again at Windows sign-in. Once configured, double-click `Start-LiteLLM.cmd` to start both services. Credentials and logs stay in the ignored `.runtime` directory, which setup restricts to the current Windows account; the tunnel's metrics listener is local only

In Virtual Keys, create one key per person, choose the available model deployments and set any `max_budget` you want. Leave `budget_duration` unset for a lifetime cap and avoid assigning a shared team unless intended. Give the teammate only their virtual key and `https://api.example.com/v1`. Keep the master key, admin password, Azure key and Cloudflare credentials private. Use the UI to change budgets, inspect spend and block or delete a key. Preserve normal authentication on the public portal

`Verify.ps1` checks readiness, the admin login, authentication and a temporary zero-budget key without calling Azure. It deletes the temporary key afterward. Provider inference is a separate check; a functioning portal does not establish that Azure accepts the supplied inference credentials

Reservations and fail-closed budget enforcement are enabled. Redis coordination must work before requests can be forwarded. Background Responses and batches remain blocked by the existing readiness callback because this configuration has no durable asynchronous accounting worker. Spend is estimated from the fork's pinned pricing catalogue and provider usage. It is not a real-time Azure invoice. Changing a limit does not cancel an already-running Azure request

The single worker caches authentication in memory while Redis continues coordinating spend and reservations. Provider requests use HTTPX. Database spend reports flush about every 10–15 seconds to reduce background contention; budget counters still update per request. Use graceful shutdown to flush pending reports. First-response latency includes provider generation, remote budget checks and the public tunnel, so it is not guaranteed to stay below one second

The pricing catalogue is copied from the fork during setup. Restart after approved pricing changes. The configuration starts with an empty model list and does not require Azure credentials. Models added through the Admin UI are loaded from the database; catalogue entries do not provision provider deployments. Hosting from the laptop and the named Cloudflare tunnel avoid VM hosting fees; provider model calls and existing database or Redis usage remain subject to their own quotas

References: [Cloudflare named tunnels](https://developers.cloudflare.com/tunnel/), [LiteLLM virtual keys](https://docs.litellm.ai/docs/proxy/virtual_keys), [LiteLLM budget enforcement](https://docs.litellm.ai/docs/proxy/users)
